# Importing expenses from receipts

**For the person encoding receipts.** This is how the Expenses import works, column by
column, what gets a row rejected, and three worked examples you can check your file
against.

The template is generated by the Portal for one client at a time: *Expenses → Import →
Download template*. It is an `.xlsx` with five sheets. You fill in two of them.

| Sheet | Who it is for | What you do |
|---|---|---|
| **Instructions** | you | read it; the two sample rows at the bottom are examples, never imported |
| **CLIENT** | the importer | fill in **Period From** and **Period To**; change nothing else |
| **EXPENSES** | the importer | one row per receipt, starting at row 2 |
| **REFERENCE** | you | the allowed Document Types, the VAT treatments, the TIN formats |
| **COA** | you | the client's chart of accounts — pick a code marked **Allowed = Y** |

When you are done: *Import → Dry run*. The dry run checks every row and tells you, row by
row, what would be **posted**, **held** or **rejected** — and writes nothing. Fix what it
flags, dry-run again, then *Import*.

## What the importer does with a row

1. **Reads the CLIENT sheet first.** The file must have been generated for the client you
   are importing into and must say `Template Version: expenses-v2`; Period From and To must
   be filled. Otherwise the whole file is refused and no row is read.
2. **Checks every row** against the rules below. Nothing is written until every row has
   been checked.
3. **Splits** the row into one record per treatment present (Vatable, VAT-Exempt,
   Zero-rated, Other Non-vatable). All of them share the date, vendor, reference number,
   document type and source file.
4. **Stamps** each record with the client's VAT treatment (`vatClaimable`), so a later
   change to the client's registration cannot reinterpret it.
5. **Writes** each row's records together — a row never lands half-written — and records
   an audit entry per record and one per upload with the counts.

### Treatments: what lands on the record

The client's registration (shown on the CLIENT sheet) decides this. You never choose it.

| Column | VAT-registered client | Non-VAT (percentage tax) client |
|---|---|---|
| Vatable + VAT | one record: **net** = Vatable, **input VAT** = VAT (claimable), category `DOMESTIC_PURCHASES`, `vatClaimable = true` | one record: **amount** = Vatable **+ VAT** (the gross is the expense), the VAT kept as a figure, `vatClaimable = false` |
| VAT-Exempt | one record, category `DOMESTIC_NO_INPUT_TAX`, `vatClaimable = false` | one record, no category, `vatClaimable = false` |
| Zero-rated | same as VAT-Exempt | same |
| Other Non-vatable | same as VAT-Exempt | same |

`DOMESTIC_NO_INPUT_TAX` is the Portal's name for "no VAT applies" on a purchase (2550Q item
48, amount only). The three no-VAT columns are told apart in the import result and in the
audit trail, not on the record itself.

### Outcomes

| Outcome | Meaning | Counts in totals? |
|---|---|---|
| **posted** | written and live | yes |
| **held** | written, but waiting for an accountant: the document is not an official invoice, or COA Code was blank | **no** — not in the tax estimate, the dashboard, the financial statements or any summary, until an accountant posts it |
| **rejected** | not written; the message says why | — |

A **Needs Review = Y** row, or a row with no Vendor TIN, is still posted (or held, by the
rules above) — it just carries the flag and your Remarks so an accountant can look at it.

### What gets a row rejected

- Date blank, not a real date, or outside the CLIENT period.
- Document Type blank or not on the list.
- Vendor TIN in a form other than the four allowed (a *blank* TIN is fine).
- No vendor name at all (Registered Name, or Lastname + Firstname).
- Reference Number blank on an invoice document type, or longer than 32 characters, or
  typed as a number so long Excel dropped its digits — type it as text.
- Gross Total blank; no breakdown at all; Vatable without VAT (or VAT without Vatable); the
  breakdown not adding up to Gross Total within 0.01.
- COA Code that is not on the chart, or an account not marked Allowed = Y.
- ATC without Withholding Amount, Withholding Amount without ATC, an ATC that is not a BIR
  code, or withholding larger than the gross.
- Needs Review anything other than Y / N.
- **Duplicate in the file:** the same vendor TIN + reference number + date + gross as an
  earlier row (vendor TIN + date + gross when there is no reference). The first row stays;
  the later one is rejected and the message names the earlier row.
- **Already in the books:** a vendor TIN + reference number that already exists for this
  client, or — with no reference — the same vendor TIN, date and amount. The message names
  the existing record.

Whole-file refusals: not an `.xlsx`; a changed header row; another client's file; an
unknown template version; a blank period; more than 1,000 rows.

## Three worked examples

All three use the same supermarket receipt — vatable **2,952.01**, VAT **354.24**,
VAT-exempt **887.96**, total **4,194.21** — and a water-delivery slip. The numbers are
invented.

### 1. The mixed receipt, non-VAT client

The row you type is the receipt as printed:

| Date | Document Type | Vendor TIN | Vendor Registered Name | Reference Number | Vatable | VAT | VAT-Exempt | Gross Total | COA Code | Source File |
|---|---|---|---|---|---|---|---|---|---|---|
| 2026-08-14 | SALES_INVOICE | 000-222-333-00000 | Invented Supermart Inc | 00000000000000000012345 | 2952.01 | 354.24 | 887.96 | 4194.21 | *(an Allowed code)* | IMG_0001.jpg |

What the importer writes for a client who is **not** VAT-registered — two records:

| Record | Amount | VAT figure | vatClaimable |
|---|---|---|---|
| VATABLE part | **3,306.25** (= 2,952.01 + 354.24: the gross is the expense) | 354.24 kept as a cost figure | false |
| VAT_EXEMPT part | **887.96** | — | false |

3,306.25 + 887.96 = 4,194.21. Outcome: **posted**.

### 2. The same receipt, VAT-registered client

Same row. Two records, but the VAT is now a claim, not a cost:

| Record | Amount (net) | Input VAT | Category | vatClaimable |
|---|---|---|---|---|
| VATABLE part | **2,952.01** | **354.24** | DOMESTIC_PURCHASES | true |
| VAT_EXEMPT part | **887.96** | — | DOMESTIC_NO_INPUT_TAX | false |

2,952.01 + 887.96 + 354.24 = 4,194.21. Outcome: **posted**.

### 3. A delivery receipt with no TIN

| Date | Document Type | Vendor TIN | Vendor Registered Name | Reference Number | Other Non-vatable | Gross Total | COA Code | Source File |
|---|---|---|---|---|---|---|---|---|
| 2026-09-02 | DELIVERY_RECEIPT | *(blank)* | Invented Water Delivery | *(blank)* | 500.00 | 500.00 | *(an Allowed code)* | IMG_0002.jpg |

One record of **500.00**, `vatClaimable = false`. Outcome: **held**, **Needs Review** on,
with two messages: *No Vendor TIN on the receipt: the row is flagged for review* and
*Held: DELIVERY_RECEIPT is not an official invoice — an accountant must post it.* The
blank reference is allowed because a delivery receipt is not an invoice. The 500.00 does
not appear in any total until an accountant posts it from the Expenses page.

## After the import

- The Expenses page lists every record, with its **status** (posted / held), the Needs
  Review flag, the document type and the source file.
- A held record is posted from that page once an accountant has decided what it is. A held
  record with no account cannot be posted until an account is assigned to it.
- Every upload leaves one audit entry with the counts (rows, posted, held, rejected) and one
  per record, so a batch can always be traced back to its file.
